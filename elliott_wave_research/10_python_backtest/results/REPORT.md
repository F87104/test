# 検証レポート: エリオット波動 5波狙い手法は勝てるのか？

> Python バックテスト結果（H1 / 2014–2026・複数通貨）
>
> **重要訂正版 (2026-05-27)**: 初版レポートには CSV パースバグがあり、
> 結果は完全に無効でした。本版はその修正後の真の結果です。

## 訂正の経緯

初版レポートでは「USDJPY +18.49%, PF 3.62」など華々しい結果を報告していましたが、
これは CSV パーサが `<DTYYYYMMDD>` + `<TIME>` の 2 列を持つフォーマットを誤読し、
**時刻のみ（"0000", "0001"...）でソートしていたため、12 年分のデータが時系列順では
なくなっていた**結果でした。雲の計算は「過去の同時刻データの集合」に対して行われ、
偶然トレンドの方向が揃った疑似時系列を作り出していたという、典型的なデータリーケージ
に近い問題です。

修正コミット: パーサが `dtyyyymmdd` カラムを優先的に拾い、`time` 列と連結するように変更。

## TL;DR（訂正版）

**結論: 書籍通りに機械化したエリオット波動 5 波狙いは、Python バックテストで
明確なエッジを示さない。**

H1 / 9 通貨 / 11 年で検証した結果、ほぼ全ての通貨でリターンが横ばい〜マイナス。
唯一プラスを継続したのは CHFJPY と SPX500 のみで、それも +0.3% / +1.0% 程度。
書籍通りの厳格パラメータでも、ルールを緩めても、同じ傾向。

**勝率は 28–37% / PF 0.4–1.2 と、勝率低めだが Trail で稼ぐタイプのトレンドフォロー
としては明確なエッジが見えない。** 書籍が「**経験で身につけるフラッグの角度や
カウントの微修正**」が決定的だと強調していたことが、定量的にも反映されています。

## 解釈

書籍が一貫して強調していた以下の点を、定量検証は皮肉にも証明した形になりました。

> 「フラッグの角度や、ヒゲの飛び出しの許容範囲など、このあたりは経験を積んでいく
> 中で自分なりの基準を作り上げていかなければいけません。」（§38 著者総括）

つまり、**裁量部分を機械的なフィルタに置き換えた途端、手法のエッジはほぼ失われる**
ということが数字で示されました。著者の「カウント修正」「相場の勢いの感覚」
「通貨強弱との組み合わせ」が、実は手法の核だったわけです。

## 機械化版で勝てるようにするには

現状の機械化版を「勝てる手法」にするには、以下のいずれかが必要そうです。

1. **エントリーフィルタの大幅強化**
   - 通貨強弱の指標化＋閾値
   - ボラティリティ・レジーム（ADX, ATR%）
   - セッション制限（NY オープン後など）
   - 過去 N 本のトレンド一貫性（線形回帰の R²）

2. **出口戦略の最適化**
   - チャネル ATR トレールではなく、SR ベースのトレール
   - 部分利確のタイミング微調整
   - 時間ベース撤退（保有 N 本で利益確定）

3. **時間足変更**
   - M15 (書籍推奨の「短期足」)、M5 にも対応してマルチ TF で精度確認
   - D1 への変更で「ノイズ削減」効果検証

4. **シンボル特化チューニング**
   - 通貨別にパラメータを個別最適化
   - ただし過学習リスクが高い → ウォークフォワード必須

## Pine 戦略との不一致

参考: TradingView Pine 戦略 (`09_pine_strategy/`) で USDJPY H1 (2023-2026) を回すと
**1 トレードしか発生しない**ことを確認しました。一方、Python では同期間で 10 トレード
程度発生します。原因として考えられるのは:

1. **TradingView の `max_bars_back` 制限**: デフォルトで 2 万本程度しか過去参照しない
2. **OANDA データ vs リポジトリ CSV の微差**: ヒゲや終値が微妙に違う
3. **HTF (`request.security`) の挙動差**: Pine は厳密に H4 を取得、Python はバー集約で代用

このすれ違いは「次に解決すべき課題」の筆頭です。
